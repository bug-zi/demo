## 一、docs 文件夹升级

### 目标结构

```text
docs/
├─ README.md                  # 导航 + 规范（吸收 docs.md 后删除原文件）
├─ logs/                      # 开发日志流水，按日期一文件
│  └─ YYMMDD.md               # 例：260909.md
├─ project/                   # 功能域现状文档（记录"现在是什么"）
│  ├─ 00-总览.md              # 产品一句话 + 技术栈 + 数据流，面向队友/评委的入口
│  ├─ 人设系统.md
│  ├─ 对线规则.md
│  ├─ 报告与导出.md
│  └─ 视听与界面.md
├─ draft/                     # 未定稿的想法/讨论草稿区
│  ├─ 寻找合适选题.md          # 从 docs/ 根目录迁入
│  └─ 260909-终局形态与拓展方案库.md   # 本文件
├─ 黑客松要求.md               # 留在根目录：全队常看的外部约束
└─ 杠精陪练房-创作计划书.md    # 留在根目录：立项书，内容冻结不再更新
```

### 各目录职责

- **README.md**：docs 的导航页与使用规范，说明各子文件夹用途、日志格式约定。
- **logs/**：只记流水，不复盘（复盘和想法进 draft/）。文件名 `YYMMDD.md`，当天首次写入时创建。条目格式：

  ```markdown
  ## HH:MM ｜ 标题
  - 做了什么
  - 动了哪些文件
  - 关键决策及原因
  - 怎么验证的
  ```

  最新条目放在文件最上方。
- **project/**：按功能域划分的现状文档，每篇建议不超过 120 行，顶部标注对应的源码文件，方便对照。
- **draft/**：未定型的功能点子、方向讨论、备选方案暂存。定稿后要么转正（进 project/ 或代码），要么标注废弃。

## 二、终局形态：话术健身房

### 决策

三个候选中选定 **形态一：话术健身房** —— 多场景高压对话陪练平台，杠精陪练房（GANG.AI）是平台的第一间房。

（落选方案：形态二「杠精竞技场」单一机制电竞化——天花板受限于梗的寿命、护城河浅；形态三「如果当时……」校园分支模拟器——核心机制换成分支树，现有资产复用最少、4 天内风险最高。）

### 决策依据

1. **DNA 洞察**：从《寻找合适选题》到《创作计划书》，迭代过的所有方向（杠精陪练房/社死预演厅/宿舍外交部/尴尬逃生舱/校园人生模拟器）共享同一段 DNA——**把一场现实中躲不掉的高压对话，变成可重复、可量化、可复盘的游戏对局**。现有对局引擎比"吵架"更通用：把怒气值换成体面值/关系损耗，把软肋换成对方底线，就是一台通用高压对话对局机。
2. **赛后定位 = 看这 4 天反响再定** → 终局必须留活口：黑客松 demo 就是平台的第一间房，反响好就开新房（C 层砖块），反响一般它也是独立完整的游戏。**零死路工作。**
3. **定位语**：娱乐为壳、训练为核——"没人需要学吵架，但人人都需要演练一次难开的口"。

### 260911 增补 · 多模块定案（A 层优先 + 地基先行）

与新功能「多模块扩展」条目商定的排期与形态决策（详见 `design/idea/` 三页纸）：

- **资料库**：查阅 + 收藏 + 自建笔记（localStorage），内容 = 现有素材 + AI 初稿 + 人工筛；广场/UGC 推迟赛后，本地笔记为其留种子。
- **好友PK = B2 落地变体**：同屏 hot-seat（远程双设备需信令/后端，与纯前端约束冲突，明确留赛后）；真人轮流作答 + AI 逐轮评分 + 终盘复盘，为全项目唯一强依赖远程 AI 的模块（本地粗评兜底）。9.12 晚时间盒 4-6h，跑不通由开发者拍板砍掉留档。

### 两条工程纪律（保证随时可加可改的前提）


1. **引擎不许焊死**：所有人设/软肋/指标数据只进 `src/data/`，数字规则只进 `src/lib/duel-engine.js`，`src/main.js` 不出现人设硬编码——C 层任何一块砖要加时，改数据不改骨架。
2. **平台叙事只进文档不进 demo**：愿景在介绍文档里讲，demo 只演建成的——画饼留给文档，惊喜留给现场。
