## 20:57 ｜ 修复：背景图/图标 404 与「深浅色不对」——静态资源迁移 public/

- 做了什么：用户实测发现背景图不显示、图标不加载、组件深浅色异常。定位出两层根因：① url() 写在 CSS 自定义属性（--bg-full/--icon）里，esbuild 不重写；② styles.css 经 index.html <link> 引用、不在 Vite 模块图里，即便 url 写在普通声明里 dev/build 也都不重写（dev 被 SPA fallback 用 index.html 顶成 200/HTML，解码必败；build 报 "didn't resolve" 且不产出资源）。修复：资源从 src/assets/ 迁到 public/assets/，CSS 全部改绝对路径 /assets/...，body 背景图按主题用 :root[data-theme] body 属性选择器直接声明，图标改 mask-image 普通声明
- 动了哪些文件：public/assets/（webp×2 + icons/12 svg，自 src/assets/ 迁入）、src/styles.css（url 全改绝对路径 26 处 + body 背景改长声明 + mask 改 mask-image）、src/assets/ 删除、docs/project/视听与界面.md、CLAUDE.md（资源位置与 url 规则）、本日志、工作台第1轮条目补记
- 关键决策及原因：修法在「CSS 改走 JS import（Vite 正统，但 Node 侧 dom-check 无法 import .css，要加 loader 桩）」与「public/ + 绝对路径（dev/build/preview 行为一致、零 JS/测试改动）」之间选后者——本项目铁律是离线可玩、怎么跑都得对；顺带教训：此前只验证了 computed style 字符串，没验证资源真实加载（200 其实是 HTML fallback），本轮补了 network resource entries + 截图像素双重验证
- 怎么验证的：dev curl /assets/bg-light.webp → 200 image/webp、/assets/icons/settings.svg → 200 image/svg+xml；浏览器 performance resources 显示 11 个资源真实加载（含 transferSize）；两主题截图像素分析（浅色页缘 #FDE9EA 粉晕 / 深色页缘 #0D2B69 宝蓝光晕 = 背景图真实渲染；深色内容区 lum 24-41 白字对比充足）；build 无 "didn't resolve" 警告且 dist/assets 齐全（2 webp + 12 svg，CSS url 为绝对路径）；npm run smoke 9 绿 + dom-check 全部通过
