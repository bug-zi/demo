# 嘴强王者 2.0（多场景分类 + 改名 + 反向局）

> 状态：方向已与开发者对齐（260911），待开发者说「立项」进 design/<模块>/
> 排期：由开发者自行协调｜来源：开发者 260911 提出（项目定位从单一杠精对话扩为多场景分类）

## 是什么

应用升级为多场景话术竞技平台「**嘴强王者**」：对线选人屏按场景分类分组——

- **杠精房**（点火局）：杠精网友、阴阳怪气亲戚（后续可补大爷大妈等）
- **谈判房**（点火局）：画饼老板、砍价摊主、甲方
- **情商房**（灭火局·反向）：哄人/说服场景，占位「即将开放」，人设内容后补

杠精房/谈判房沿用现有「点火」怒气引擎（把对方激到破防=赢）；情商房为**灭火局**：对方怒气 100 起步（正在气头上），玩家几轮内把怒气降到阈值以下=赢，说错话怒气反弹。大厅三模块卡结构不动，分类只切在选人屏。应用名改「嘴强王者」（谐音最强王者，三类统一为「嘴上分高下」，与段位/称号体系咬合）；「话术健身房」降为副标语保留叙事连续性；原「杠精陪练房」名号由杠精房分组继承。

## 为什么

- 人设已溢出「杠精」范畴（甲方/砍价是谈判不是抬杠），旧名限制认知；改名后三类场景在同一命名下立得住
- 分类是玩家找对手的第一心智轴（「我想练哪个场景」），比按人设平铺更可扩展，人设越多越明显
- 结构上是子集升级：category 先做选人屏分组标签，将来若走「类=房=新指标」（方案库 C1 新房路线）不用返工

## 最小版本（框架先行）

- `src/data/categories.js` 分类登记表：id / 名称 / 排序 / 模式（fire 点火 · extinguish 灭火）/ 锁定态；`personas.js` 每个 persona 加 `category` 字段
- 选人屏按类分组渲染（组标题 + 卡片）；情商房空态「即将开放」占位（同大厅锁定卡模式，不做死链）
- 灭火局引擎：`duel-engine.js` 支持按模式设定初始怒气与反向胜负判定；称号/结算文案随灭火局适配（具体数值与文案留 designs-specs 细定）
- 改名 + 版本：index.html `<title>`、顶栏/大厅主标题改「嘴强王者」（副标语「话术健身房」）、README 标题与简介、`package.json` name/version `2.0.0`；部署域名 gang.debugzi.com 不动（域名≠产品名）；创作计划书内容冻结不改

## 关键决策（已与开发者对齐）

- 分类切在**选人屏**而非大厅——保住刚落地的大厅结构，改动最小，且是「大厅按类开房」「类=房=新指标」两条路线的子集，升级不返工
- 情商类做**反向局**而非占位不上——三类玩法有节奏差异（点火/点火/灭火），引擎仅改初始值+判定方向，其余规则复用
- **框架先行**——分类/灭火引擎/改名/版本号先落，情商类人设内容后续按 A1 同模式补（纯数据，走 personas.js 既有通道，随加随有）
- 命名定「嘴强王者」（候选嘴力全开/开口赢/伶牙俐齿训练营已否决）——竞技感+网感罩住三类，现场传播力最强
