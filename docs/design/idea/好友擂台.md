## 是什么

两个真人同屏轮流 PK：随机给一个高压对话场景 → P1 限时作答 → **交接屏**（遮住答案防偷看）→ P2 作答 → AI 逐轮评分（0-10 + 短评）→ 数轮后终盘 AI 复盘（双方表现 + 金句 + 胜者）。现场可拉评委/观众下场互动。

技术形态：**独立引擎文件**（不往 `duel-engine.js` 塞第二种玩法，守住「引擎不许焊死」纪律）；场景卡 `src/data/scenarios.js`；评分走已接入的远程 AI（`llm.js` 增新 prompt/schema）。

## 为什么

- 「多人房」方向的第一块砖：真人 vs 真人 + AI 裁判，现场互动炸点，可拉评委/观众下场。
- 同屏 hot-seat 零服务、零网络通信依赖，规避「两设备互连需要信令/后端」与纯前端约束的冲突（远程双设备版明确留给赛后）。

## 最小版本

- 一局完整流程可玩：随机场景 ≥ 5 张、3 轮问答、逐轮评分、终盘复盘报告。

## 关键决策（已与开发者对齐）

- 通信方式：同屏轮流 hot-seat（远程双设备 / 手动接力码均已否决）。
- **全项目唯一强依赖远程 AI 的模块**：无 key / 调用失败时本地启发式粗评兜底 + 提示「配置 AI 体验更佳」，不留死路；本地引擎关键词法评不了自由文本，此不对称性在模块文档显式标注。
- 无 key 时的降级评分细节、场景卡字段 schema 留到 designs-specs 细定。
