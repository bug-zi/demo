# 好友擂台 · 设计意图

1. **同屏 hot-seat 轮流 PK**：随机高压场景 → P1 限时作答 → 交接屏（遮答案防偷看）→ P2 作答 → 逐轮评分（0-10 + 短评）→ 3 轮后终盘 AI 复盘（双方点评 + 金句 + 胜者）。远程双设备 / 接力码均已否决，零服务、零网络通信依赖。

2. **独立引擎文件**：`src/lib/arena.js` 独立于 `duel-engine.js`，不往对线引擎里塞第二种玩法——「引擎不许焊死」纪律。场景卡 `src/data/scenarios.js`，视图自包含（`src/ui/arena.js` + `arena.css`，同话术资料库四件套形态）。

3. **全项目唯一强依赖远程 AI 的模块**：评分与复盘走 `llm.js` 已有的远程链路（settings-dialog 配置），Anthropic / OpenAI 兼容双路都接；无 key 或调用失败时**本地启发式粗评兜底 + 「接入你的 AI 体验更佳」提示，不留死路**。本地关键词法评不了自由文本的不对称性，在模块文档显式标注。

4. **胜负判定归引擎不归 AI**：总分由逐轮分数确定性累加，胜者/平局由 `arenaResult()` 判；AI 复盘只产文案与金句，与引擎判定冲突时以引擎为准——延续「模型建议、引擎结算」的对线哲学。

5. **min 版本即全部范围**：≥5 张场景卡（做 8 张）、3 轮问答、逐轮评分、终盘复盘。评委/观众下场互动不进本轮。答题限时固定 60 秒（到点自动交卷，空答记弃权），不接对局设置里的回合时限——擂台是派对局，紧张感是特性。

6. **离场即弃局**：擂台中途「← 大厅」直接放弃整场（对局的「切走不销毁」不适用于此）——3 轮 ×2 分钟的轻局，续局价值低于状态机成本；大厅主卡不挂擂台进行中角标。视图须带 dispose 契约：离开时清掉答题倒计时的 interval，不留幽灵计时器。

7. **验收以 `node scripts/arena-check.mjs`（新脚本，四节：数据 / 引擎 / 评分适配 / 视图）为准**；dom-check 加大厅接线一节；smoke / library-check / build 只许绿不许动既有断言。顺手修 `llm.js` anthropicTurn 的 `ctx` 引用 bug（贴纸轮引入，Anthropic 路径一调用即 ReferenceError 被吞成降级）——评分模块强依赖远程链路，这条通道不能再是坏的。
