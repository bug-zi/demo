# 3.0 大版本升级总方案：闯关战役 + 成长经济 + 成就墙 + AI 美术

> 状态：**已立项**（260912 开发者确认）｜ 流程：轻量版——各模块依本方案直接出 designs-specs，见 `3.0人设扩充/` 与 `美术升级/` 两个并行模块 ｜ **已归档：260912 成长系统三阶段（M1/M2/M4）+ M6 打磨全部落地，现状文档见 `../../project/成长系统.md`**
> 版本跨度：2.0.0 → 3.0.0 ｜ 起草：260912 ｜ 决策记录见 §1，开放项见 §11

## 0. 一句话

在现有「三房对线」骨架上叠一层**玩家成长系统**：每间房变成一条按难度爬升的闯关梯（§3），输了掉心、赢了给钱给经验（§4），成就墙发金币发称号（§5），再由 AI 生图把人设、房间、徽章全面视觉化（§6）。引擎骨架不动，成长层全是新增横切模块。

**为什么是 3.0**：2.0 解决了「有多样对局」（三房 + 灭火局 + 资料库 + 擂台），但一局打完即终点，没有「再打一局」的理由。3.0 补上留存闭环：目标感（关卡）→ 张力（生命）→ 奖励（金币/经验/成就）→ 装饰（称号/美术）。

## 1. 决策记录（已与开发者确认）

| # | 决策点 | 结论 |
|---|---|---|
| D1 | 多局结构 | **房内闯关梯**：每房人设按难度排序成关卡线，打赢当前关解锁下一关；三房梯子相互独立 |
| D2 | 成长深度 | **生命/体力制**：输局扣生命，心池见底不能开局 |
| D3 | 生命规则 | **全局心池**：上限 5，输局 −1 胜局不扣，每 30 分钟自然回 1 颗，50 金币买 1 颗，升级/成就也送；设置里有「演示模式」（无限生命）兜底现场演示 |
| D4 | 成就定位 | **成就产金币**：成就解锁一次性发币，与 D3 经济闭环打通（防刷见 §5.4） |
| D5 | 美术范围 | **全量四类**：人设立绘头像 / 房间场景背景 / 成就徽章称号卡 / 演出与战报装饰；离线批量生成，不引入运行时依赖 |
| D6 | 人设规模 | 每房 5–8 人：**基线每房 6（共 18）**，冲刺每房 8（共 24），分批交付 |

## 2. 总体架构

### 2.1 新增横切层：玩家档案（player profile）

```
src/lib/profile.js   ← 唯一的成长数据层（localStorage 键 gang-ai:profile:v1）
  数据：xp / level / coins / hearts / lastRegenAt / cleared:{roomId:[关序号]}
        achievements:{id:时间戳} / equippedTitle / stats{wins,losses,streak,...}
        demoMode
  纯函数：tickHearts() 惰性结算自然恢复（读时算，不挂定时器）
          grantBattle({win,difficulty,isFirstClear}) → {xp,coins,heartsDelta,levelUp?}
          evaluateAchievements(profile) → 新解锁列表
  存储防御：同 settings.js/notes.js 模式（坏数据收敛默认值，schema 版本号字段）
```

所有屏（选人/对局/战报/大厅/成就墙）只从 profile.js 读写，经济数值集中在文件头 `ECONOMY` 常量表，调平衡只改一处。

### 2.2 屏幕状态机变化

现有 `lobby / select / duel / report / library / arena` 六屏**全部保留**，新增：

- `wall`（成就墙屏）：从大厅名片卡进入，结构照 library/arena 模式（`createWallView()` + `dispose` + 独立 css）
- `select` 屏从「自由选人」重构为「闯关梯列表」（§4.1）
- `lobby` 新增「我的名片」卡（等级/金币/心/佩戴称号/成就进度）
- `report` 屏追加「结算区」（经验条动画 / 金币入账 / 心变动 / 成就解锁 toast 队列）

### 2.3 存量兼容

- 新键 `gang-ai:profile:v1`，不迁移旧数据（与项目「改名不动存量键」同一原则）；现有 settings/notes/favorites/主题皮肤键全部不动
- `difficulty` 字段今天只在选人卡画星标（main.js:331），3.0 起接管为**关卡排序 + 奖励系数 + 引擎阻力参数**三个用途
- 情商房 `categories.js` 的 `locked: true` 随情商房人设落地删除，占位卡自然消失

### 3.2 引擎阻力参数（把「难」从数值搬到机制）

新增人设可选字段，现有 5 人不写=向后兼容：

```js
guard: 0.85   // 玩家有效输出折扣系数（0.7–1.3），recordTurn 里乘到 delta 上
drift: 3      // 每回合环境漂移：fire 房 -3（对方自己消气，更难打满），
              // extinguish 房 +3（怒气自己回升，更难哄平）；0 为无漂移
```

- 高星关不再只是「血更厚」，而是**边打边漏气**：fire 高星关有 `drift` 负漂移（不持续输出怒气会自己回落），extinguish 高星关有正漂移（不持续哄怒气会回升），逼玩家连续命中
- 全部实现收敛在 `recordTurn()`，smoke 加对应用例

### 3.3 人设内容交付规格

每个人设 = 一份完整 `personas.js` 条目（身份文案 / opener / presets / 3 软肋 keywords+deltas / 3 阶段台词各 3 条 / softspotReactions / breakdown / finale 配置）。情商房人设照 extinguish 方向写台词（消气阶梯），演出 kind 从现有 5 种里选或走通用兜底。**每人设一条独立交付单元**，方便并行认领与逐一过检。

## 4. 方向二：房内闯关梯 + 成长经济

### 4.1 闯关梯规则

- 每房 = 关卡线，`difficulty` 升序即关卡顺序；同星数按数组序
- 三种关卡态：`🔒待解锁`（显示「???」+ 星数预告，不可点）→ `▶当前关`（高亮）→ `✅已通关`（可复刷）
- 打赢当前关 → 本关标记已通关 + 下一关解锁；三房进度互不影响、房间均无需跨房门禁
- 复刷已通关卡随时可打，奖励按复刷档（§4.4）
- 选人屏顶部常驻心池条（❤×N + 下一颗恢复倒计时 + 「50 币补心」），演示模式下隐藏
- 心 = 0 时所有「开战」按钮禁用，弹引导（等恢复 / 买心 / 开演示模式）

### 4.2 生命（心池）

| 项 | 值 | 说明 |
|---|---|---|
| 上限 / 初始 | 5 / 5 | 新玩家满心 |
| 扣除 | 输局 −1 | 胜局、平局（fire 和局）不扣 |
| 自然恢复 | 每 30 分钟 +1 | `lastRegenAt` 惰性结算，离线也在回；读档即算，不挂后台定时器 |
| 购买 | 50 金币/颗 | 只补到上限 |
| 升级奖励 | 每 5 级 +1 颗 | Lv5 / Lv10 / … |
| 成就奖励 | 部分成就送心 | 见 §5.3 |
| 死锁兜底 | 时间恢复始终生效 | 币不足 50 也能等回心，永不卡死 |
| 演示模式 | 设置弹窗开关 | 无限心、隐藏心条；状态存 profile，评审现场一键兜底 |

### 4.3 经验与等级

| 项 | 值 |
|---|---|
| 胜局经验 | `30 + 10 × difficulty`（d1=40 … d5=80） |
| 负局经验 | 15（安慰值，金币为 0） |
| 升级曲线 | 升到下一级需 `100 + (level−1) × 50`（Lv1→2 要 100，Lv2→3 要 150 …） |
| 升级奖励 | +100 金币；每满 5 级额外 +1 心 |
| 等级用途 | 3.0 内为纯成长线 + 每 5 级送心；称号佩戴与名片展示挂钩等级徽章 |

### 4.4 金币

**产出**：胜局首通 `50 + 20 × difficulty`（d1=70 … d5=150）；复刷同关 = 首通 × 30%（取整）；成就一次性发币（铜 50 / 银 100 / 金 200 / 王者 300）；升级 +100。

**消耗**：买心 50/颗；装扮类（§5.2 称号框 / 名片主题，M4 批次小体量上架）。

**防刷**：复刷降档 30% 是唯一刷币口，边际收益递减；成就一次性；无每日任务（不做登录留存钩子，黑客松 demo 不需要）。

### 4.5 结算流程

`finish()` 判出胜负后，在现有战报渲染前调 `profile.grantBattle()`：

```
胜/负 → 经验/金币/心 计算与入账 → 升级检测 → 成就扫描（evaluateAchievements）
      → 战报屏追加「结算区」：经验条动画 + 金币 +N + 心 ±N + 升级横幅 + 成就 toast 队列
```

- 结算只发生在 `state.screen === 'report'` 渲染路径，中途去大厅回来数据已在 profile，不重复入账（`grantBattle` 以 duel id 幂等）
- 战报分享卡（share-card.js）追加佩戴称号一行；立绘头像接入为可选增强

### 5.4 防刷与数据面

- 成就条件全部读 profile 累计值与一次性事件，**没有可重复解锁的成就**；复刷降档让刷关收益薄

- `stats` 面只增不减，成就判定为纯函数，`profile-check.mjs` 可穷举测试

## 6. 方向四：AI 生图美术升级

### 6.1 生成管线（离线批量，零运行时依赖）

```
风格指南（一页纸：统一风格关键词 + 负面词 + 每类模板 prompt）
  → 每类先出 1 张小样，开发者拍板风格
  → 用 gpt-image2 按模板批量生成（AI 执行，开发者提供 key/endpoint）
  → 开发者筛选定稿 → 统一压缩/裁切 → 入库 public/assets/art/
  → 命名规范：art/portraits/{personaId}.png · art/bg/{screenId}.jpg
             · art/badges/{achievementId}.png · art/frame/{win|lose}.png
```

- 生成物是**静态资产**，与 `qrcode-generator` 同级对待：构建期外置，运行时只读文件
- 接入走 `public/` 绝对路径（`/assets/art/...`）——`<link>` 加载的 CSS 里 url() 不会被 Vite 重写，这是既有踩坑结论（背景图现行做法），美术资产全部沿用
- 头像走现有 avatar 通道替换：persona 增加可选 `portrait: '/assets/art/portraits/xxx.png'`，无 portrait 时回退现有 SVG 图标（数据缺失即降级，选人卡/对局气泡/分享卡三处同源）

### 6.2 风格指南（首版关键词，待小样确认）

- **统一基调**：中式现代漫画插画风、明快平涂色块、干净单色渐变底、胸像构图、微夸张表情、**画面内无文字**
- **皮肤兼容**：所有资产低饱和、自带浅色底，blossom/midnight 两皮肤下由 CSS 叠半透明遮罩适配，图本身不做深浅两套
- **负面词**：写实照片感、3D 渲染、文字水印、复杂背景细节、高饱和荧光色

### 6.3 资产清单与批次

| 批次 | 资产 | 数量 | 规格 |
|---|---|---|---|
| A1 | 人设立绘头像（含现有 5 人重绘） | 18（冲刺 24） | 512×512，头像圆形安全区居中 |

## 8. 里程碑与并行轨

三条轨道可并行，轨间只在「roster 确认」「风格小样确认」两个点会合：

```
轨A 系统（串行）  M1 档案层+经济+结算+演示模式 → M2 闯关梯选人重构 → M4 成就墙 → M6 打磨
轨B 内容（并行）  roster 确认 → 批次B1 情商房6人设（情商房解锁！最大可见增量）
                  → 批次B2 杠精房+3 / 谈判房+3（每房满 6）→ 冲刺批次B3 每房+2
轨C 美术（并行）  风格指南+小样 → A1 头像 → A2 背景 → A3 演出战报 → A4 徽章
```

| 里程碑 | 内容 | 依赖 |
|---|---|---|
| M0 | 本方案过目 + roster/风格关键词确认 | — |
| M1 | profile.js + 心池/金币/经验 + 结算区 + 演示模式（配现有 5 人设即可玩，暂无锁关） | M0 |
| M2 | select 屏闯关梯重构 + 锁/通/复刷 + 引擎 guard/drift + smoke 用例 | M1 |
| B1 | 情商房 6 人设 → 情商房解锁上线 | roster 确认（不依赖轨A，但解锁体验在 M2 后最完整） |
| M4 | 成就墙 + 称号图鉴/佩戴 + toast + 资料库/擂台挂勾 + profile-check | M1（与 B1/B2 并行） |
| B2/B3 | 剩余人设批次 | roster 确认 |
| A1–A4 | 美术四批次，随做随接入 | 风格小样确认 |

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| 生命制让现场演示「没心玩不了」 | 演示模式开关（§4.2）+ 时间恢复永不死锁 |
| 数值失衡（升太快/金币通胀） | 常量集中在 `ECONOMY` 表；M6 专设试玩平衡 pass；本方案数值全部标可调 |
| 内容量大（13+ 人设） | roster 先行确认；每人设独立交付单元可并行认领；B1/B2/B3 分批上线不等齐 |

| 成就/称号与现有赛后称号双轨混淆 | 赛后称号自动入册，成就称号是第二来源；两源同表（titles 稳定 id） |
