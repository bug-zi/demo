# 皮肤系统设计方案（spec）

> 状态：待开发者确认
> 定位：样式模块第 2 轮。第 1 轮（双主题+背景图+图标体系）已落地，本轮在其上加「多皮肤」层。
> 需求出处：docs/工作台.md 新功能区（260910 用户提出），入口形态/解耦模型/白日配色已经用户拍板。

## 0. 已确认的决策（不再讨论）

1. **皮肤与深浅正交解耦**：皮肤卡只切皮肤；深浅切换仍走顶栏主题按钮 + 设置弹窗「外观」区，两套皮肤下通用。
2. 入口 = **顶栏弹层皮肤卡**（palette 图标按钮 → 小浮层，非独立页面、非设置弹窗分区）。
3. 两套皮肤：`blossom`「樱花与星夜」（现状 1:1 保留）、`midnight`「深夜聊天窗」（深色 = 原版 1:1 复刻，浅色 = 新设计「白日·暖米纸」，候选稿浏览器选型已定）。
4. 弹层对线中可开，**不暂停回合计时**（轻量即时选择，无公平性风险；设置弹窗仍暂停，不变）。

## 1. 皮肤模型

| 皮肤 id | 名称 | 浅色 | 深色 |
|---|---|---|---|
| `blossom` | 樱花与星夜 | 樱花粉 + bg-light 背景图 + 半透明卡片（现状） | 宝蓝星空 + bg-dark + 半透明卡片（现状） |
| `midnight` | 深夜聊天窗 | 白日·暖米纸：暖米底实色面板 | 深夜：炭黑暖棕实色面板（原版 1:1） |

驱动方式：`<html data-skin="blossom|midnight">` × `<html data-theme="light|dark">` 双属性正交，全部颜色走 CSS 令牌。默认皮肤 `blossom`（无 `data-skin` 时即 blossom——CSS 基础块不动）。

## 3. 皮肤级非令牌差异（styles.css）

1. **背景图关闭**（blossom 的 body 背景图在 midnight 下必须去掉）：
   ```css
   :root[data-skin='midnight'] body {
     background-image: none;   /* 写在 blossom 深色 body 规则之后，源顺序取胜 */
   }
   ```
2. **stage-pill 回原版「素底彩字」**（现版为实底药丸，midnight 恢复原版味）：
   ```css
   :root[data-skin='midnight'] .stage-pill.stage-polite   { background: var(--surface-deep); color: var(--stage-polite); }
   :root[data-skin='midnight'] .stage-pill.stage-sarcastic { background: var(--surface-deep); color: var(--stage-sarcastic); }
   :root[data-skin='midnight'] .stage-pill.stage-agitated  { background: var(--surface-deep); color: var(--stage-agitated); }
   :root[data-skin='midnight'] .stage-pill.stage-breakdown { background: var(--surface-deep); color: var(--stage-breakdown); }
   ```
   （特异性 0-4-0 盖过现版 `:root .stage-pill.stage-*` 的 0-3-0。）
3. 其余（气泡、怒气条、判定标签、战绩徽章、计时红显、fallback 标签）全部令牌驱动，零改动；战绩图 Canvas 读令牌自动跟随皮肤。

## 4. 状态层（src/lib/theme.js 扩展）

```js
const SKIN_KEY = 'gang-ai:skin';
const skinListeners = new Set();

export function getSkin()            // 读 localStorage，'midnight' 才认，否则 'blossom'
export function applySkin(skin)      // 非法值直接 return；设 documentElement.dataset.skin；广播 skinListeners
export function setSkin(skin)        // localStorage.setItem + applySkin（玩家点卡入口）
export function onSkin(fn)           // 订阅（立即回调一次当前值），返回退订函数；照 onTheme 模式
export function initSkin()           // applySkin(getSkin())
```

皮肤元数据登记 `src/data/skins.js`（弹层渲染唯一数据源，加皮肤只改这里）：

## 5. 皮肤选择弹层（新文件 src/ui/skin-popover.js）

挂 `document.body`（同 settings-dialog 模式，不走 render()，不破坏进行中对局）。

- **入口**：index.html 顶栏，引擎徽章与主题按钮之间新增：
  ```html
  <button id="skin-btn" class="ghost-btn" type="button" aria-label="皮肤选择" aria-haspopup="dialog">
    <span class="icon i-palette" aria-hidden="true"></span>
  </button>
  ```
- **浮层结构**（`h()` 构建，文本一律 textNode）：
  ```
  .skin-popover[role="dialog"][aria-label="皮肤选择"]
    .skin-pop-title  皮肤
    .skin-card[data-skin-id][class*=is-active]   ← <button>
      .skin-card-head  {皮肤名} + .skin-card-check(i-check 图标，仅 active 卡显示)
      .skin-card-desc  {一句话描述}
      .skin-card-samples  .sample.light + .sample.dark   ← 各 = 底色块+accent 色点，静态预览
  ```
- **定位**：CSS `position:fixed; top:60px; right:16px; width:300px`；`@media (max-width:560px)` 下 `left:12px; right:12px; width:auto`。
- **行为**：`open(btn)` 建层挂 body + 订阅 `onSkin` 同步 active 卡 + 监听 `keydown`(Esc) 与 `mousedown`(点层外且非入口按钮 → close)；`close()` 摘层退订。点卡 = `setSkin(id)` 立即生效，浮层**保持开着**（便于对比着切），不自动关。main.js `wireTopbar()` 接线 `#skin-btn` 开/关。
- **样式**：皮肤卡走主题令牌（--surface/--line/--accent 等），与当前皮肤联动换色；卡 hover 抬升描边。

## 6. 图标（public/assets/icons/，自托管照旧）

新增 2 个（12→14）：`palette.svg`（入口按钮）、`check.svg`（active 卡勾）。拷贝自 `@material-symbols/svg-400@0.47.2`，CSS 加 `.i-palette`/`.i-check` 两条 mask 声明（绝对路径，规则同前）。

## 7. 防闪脚本（index.html 内联段）

在读 theme 之后加：
```js
var sk = localStorage.getItem('gang-ai:skin');
if (sk === 'midnight') document.documentElement.dataset.skin = sk;
```
（默认 blossom 无需设置——CSS 基础块即 blossom。）

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| CSS 块顺序/特异性出错导致 midnight 浅被 blossom 深盖住 | 块序写死：blossom浅→blossom深→midnight浅→midnight深→midnight body 覆盖→stage-pill 覆盖；4 态像素验证兜底 |
| 弹层点外关闭误伤入口按钮（点按钮变成开→瞬间关→又开） | 外点判定排除 `#skin-btn` 自身 |
| jsdom 无 matchMedia | skin 逻辑不依赖 matchMedia，无此问题 |
| 皮肤切换时进行中的对局 | 纯 CSS 属性切换，DOM 不重建，对局状态零影响 |
