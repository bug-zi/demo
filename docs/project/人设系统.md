## 人设字段结构

```text
persona = {
  id, name, category('gang'|'deal'|'eq'), avatar, difficulty(1-5), tagline,  // 身份层
  intro, opener,                                      // 出场：人设简介 / 第一句话（情商房 opener=怒气开局）
  presets: [3 条预设话术],                             // 对线屏按钮，点一次作废一次；必须各命中一个互异软肋
  softspots: [ { key, label, delta, keywords[] } ],   // 软肋层，3 个（灭火局语义=心结）
  stages:      { polite: [3], sarcastic: [3], agitated: [3] },  // 阶段台词（情商房按消气阶梯反向写）
  softspotReactions: { [softspotKey]: [3 条] },       // 软肋被戳中的专属反应，三 key 不许缺
  breakdown:   fire 房 3 句破防演出；eq 房 6–8 句「暴怒常规池」（开局 100 怒气即此段，= 玩家最先听到的开场语言）
  finale:      { kind: 'rapid'|'quit'|'recall'|'lights-off'|'read-none', lead[], exitLine },  // 专属收场演出
               //（缺省走通用兜底「breakdown + 已退出群聊」；eq 房用消气向文案复用同五种演出）
  guard/drift: 引擎阻力参数，按星档：d1/d2 缺省(1.0/0)、d3 0.95/2、d4 0.9/2、d5 0.85/3
  portrait:    （美术轨 A1 立绘留位，无 portrait 时回退图标渲染）
}
```

- `category` 归房：`gang` 杠精房 / `deal` 谈判房（fire 点火局），`eq` 情商房（extinguish 灭火局）；未标注兜底归杠精房。分类登记表在 `categories.js`（房名/模式/hint；三房均已开放）
- `keywords` 是**子串匹配**：玩家输入（去空白后）包含任一关键词即判命中；本地引擎用它判定，远程模式下它作为示例写进提示词，模型自行判断、本地只兜底
- 回复台词的选择优先级（llm.js localTurn）：自爆反应 > 软肋专属反应 > 破防台词 > 当前阶段台词 > 通用兜底

## 软肋数值设计

- 每人设 3 个软肋，delta 域 24–34；旧标尺「三软肋合计 88–94，三软肋全中 + 补一句有效输出（+12）即破百」对非教学关人设依然成立
- **d1 教学关刻意合计 = 100**（如圣人/贩子 34/32/34）：三预设恰好破百，三手过关；灭火局 d1 反向定 84（naicha 30/28/26，100−84=16 三手消气）——点火局和灭火局的教学关节奏同构、方向相反
- 同一软肋第二次命中 delta 减半（防按着预设连点）；光靠有效输出 8 轮 × 12 不够破百——**不找软肋就赢不了**，玩法核心约束
- eq 房 delta 一律按「激怒量」直觉填正数，引擎对 extinguish 统一翻转符号（命中=高效降温）

## 新增人设检查单

1. 在 `PERSONAS` **数组中按目标关卡序插入**（插入位置即关卡序，同星按数组序）；挂 `category` 与 `difficulty`；阻力参数按星档（见上表）
2. spec 依据与写作规则：`docs/design/3.0人设扩充/designs-specs.md`（含情商房「语义反转」写作规则一节）
3. keywords ≥6 个变体、禁单字；三条预设**各命中一个互异软肋**（smoke「互异软肋」闸门把关，串键会被抓住）；软肋 keywords 必须在 opener/stages/breakdown 里有语义铺垫，不能凭空猜
4. stages 三键各 ≥3 条、softspotReactions 三 key 各 3 条、finale 五选一配齐、eq 房 breakdown 6–8 句
5. 回归全过：`npm run smoke`（18 人设逐字段过检 + 关键词自检 + 互异软肋）、`npm run profile-check`（梯序）、`npm run dom-check`（按人设名定位选卡，插关不动测试骨架）
